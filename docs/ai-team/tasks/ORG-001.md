# ORG-001: Organisation accounts, ground booking and tournaments

Status: IN_PROGRESS
Team: Lead
Service: Shared Identity, Booking, Tournaments
Depends on: Existing authenticated accounts and transactional SportSpace state

## Request

Add separate organisation accounts that can list grounds and create, publish
and start tournaments. Players can book those grounds and register teams.

## Scope And Ownership

- Lead: authentication metadata, Flask blueprint registration, integration and docs.
- Backend: `app/organisations.py` and its service-owned state namespace.
- Frontend: `auth-ui.js`, `index.html`, `organisations.js`, `organisations.css`.
- QA: isolated organisation API and UI tests; review permissions and concurrency.
- Preserve all pre-existing working-tree changes. No deployment or infrastructure changes.

## Acceptance Criteria

- Sign-up supports player and organisation accounts with distinct service permissions.
- Organisation owners can publish grounds and manage only their own events.
- Registered players can reserve a future hourly ground slot, view and cancel
  their own reservation, and register or withdraw a team before an event starts.
- Conflicting bookings and excess or duplicate tournament registrations fail
  within the same transaction that writes the resource.
- Physical tournament publication reserves the full venue interval; a failed
  reservation leaves the event in draft. Cancelling releases that reservation.
- Tournament transitions follow draft → open → live → completed, with scheduled
  start and two active teams required to start.
- The UI confirms activity only after server success and preserves failed forms.
- New organisation accounts are explicitly unverified; signup conveys no global
  awards authority or platform verification.

## Contract

All service routes use the existing session cookies and HTTPS/CSRF checks.
Mutations send JSON and `X-Dhoyo-Request: 1`. Errors contain `error`, with
400 for invalid input, 401 for missing identity, 403 for role/ownership,
404 for absent/private resources, and 409 for conflicts or invalid transitions.

`POST /api/auth/register` accepts the existing profile fields plus
`accountType: "player" | "organisation"` (default player) and required
`organisationName` for organisation signup. Session responses and `/api/auth/me`
expose `userId`, `name`, `accountType`, and `organisationId`; roles come from
persisted accounts, never browser headers or JWT claims.

| Method and path | Role | Request / response |
| --- | --- | --- |
| GET `/api/organisations` | Signed in | `{organisations: [...]}` public organisation profiles |
| GET `/api/organisations/me` | Signed in | `{organisation, grounds, bookings, tournaments}` own dashboard |
| GET / POST `/api/grounds` | Signed in / organisation | List `{grounds: [...]}` / create `{ground}` |
| GET `/api/grounds/{id}/availability?date=YYYY-MM-DD` | Signed in | `{groundId,date,timezone,slots:[{startsAt,endsAt,label,available}]}` |
| GET / POST `/api/bookings` | Signed in / player | Own `{bookings: [...]}` / reserve `{groundId,startsAt}` → `{booking}` |
| POST `/api/bookings/{id}/cancel` | Owning player | `{}` → `{booking}` |
| GET / POST `/api/tournaments` | Signed in / organisation | Visible `{tournaments:[...]}` / create draft `{tournament}` |
| POST `/api/tournaments/{id}/{action}` | Owning organisation | `{}`; action publish, start, complete or cancel |
| POST `/api/tournaments/{id}/registrations` | Player | `{teamName}` → `{registration}` |
| GET `/api/tournaments/{id}/registrations` | Owning organisation | `{registrations:[...]}` private roster |
| POST `/api/tournaments/{id}/registrations/me/cancel` | Registered player | `{}` → `{registration}` |

Ground creation fields: name, sport, city, address, IANA timezone,
integer pricePerHour (INR), opensAt and closesAt on whole hours. Slots last one
hour and use the venue timezone, from today through 180 days ahead.
Tournament creation fields: name, sport, eventType (physical or online),
offset-aware startsAt, IANA timezone, future registrationClosesAt before/equal
start, capacity (2–128), durationHours (1–12), and owned groundId for physical
events. Physical events match the ground sport and operating hours.

Service state resides under `organisationService` within the existing locked
PostgreSQL JSONB state, with explicit SQLite support for isolated local tests.
No new services run outside the current Flask application.
