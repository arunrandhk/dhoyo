# SOC-003: Personalized Social Feed And Visual Refresh

Status: DONE (demo scope)
Team: Lead coordinating Frontend, Backend and QA
Service: Social
Depends on: No production identity; shared demo identity explicitly used

## Scope And Ownership

Backend agent: `app/social.py`, registration in `app/app.py`, and
`app/tests/test_social.py`. Frontend/integration lead: files under
`app/static/sportspace/`, documentation and browser checks.

## Acceptance Criteria

- Modern responsive social feed with stories above posts.
- Star > Diamond > Gold > Silver rank order and local visibility boost.
- Interests and engagement influence the server feed; following and nearby views
  constrain results to their selected scope.
- Persistent demo social actions and 24-hour story expiry.
- Existing ground booking and tournament demos remain usable.
- Shared demo identity and static-mode limitations are documented accurately.

## Contract

See `app/static/sportspace/README.md` for concrete API endpoints. Feed returns
`{posts, stories, preferences}`; post actions return the updated post; preference
and follow actions return preferences. Server owns ranking and expiry.

## Implementation

Flask blueprint with development SQLite persistence. New social UI integrates
through the same origin, preserving the original static demo as a fallback.
Icons are vendored from Lucide with their license.

## Verification

Backend suite: 12 tests passed, including rank abuse, persistence, personalization,
local ranking, freshness, validation and story expiry.

Playwright browser checks passed for feed modes, likes, follows, preferences,
city filtering, saved posts, story viewing/creation, post persistence after reload,
offline publishing, API failure messages, and a slow-submission dialog race.
Existing booking and tournament registration flows also passed. Screenshots were
inspected at desktop and mobile sizes; no horizontal overflow at 360, 390, 768 or
1440 pixels. All post images loaded after scrolling them into view.

## Limitations

No production login, independent service deployment, real uploads, payments, or
per-user data isolation. SQLite is a local demo store, not the production service
data model. Booking and tournaments still use browser storage.
